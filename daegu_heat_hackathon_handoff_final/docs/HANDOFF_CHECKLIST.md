# 개발 인계 및 QA 체크리스트

## 분석 담당

- [ ] 구 단위 온열질환자 회귀모델의 학습 기간, 타깃 정의, 계수·변환식을 문서화한다.
- [ ] 격자 크기(100m 또는 250m), 좌표계, 거리감쇠 파라미터 `d0`, 격자 인구 배분 방식을 고정한다.
- [ ] 모든 행정동에 여섯 Feature가 같은 기준일·단위로 생성되는지 확인한다.
- [ ] `analysis_run_summary.json`의 Silhouette, 노이즈 비율, Macro-F1과 `metadata.warnings`를 발표 전 확인한다.
- [ ] SHAP을 인과효과 또는 시설 설치의 효과 추정치로 표현하지 않는다.

## Backend 담당

- [ ] `docker compose up --build` 후 `GET /health`가 `200`인지 확인한다.
- [ ] `ALLOWED_ORIGINS`를 실제 프론트 도메인으로 제한한다.
- [ ] API에는 파일 경로나 ALAN 키를 받는 endpoint를 만들지 않는다.
- [ ] `/api/v1/clusters`가 422일 때 사용자 수정 가능 메시지만 반환하는지 확인한다.
- [ ] `data/raw`와 `data/outputs`를 영속 볼륨으로 연결하고 원자료 접근권한을 제한한다.

## Frontend 담당

- [ ] 시뮬레이션 전·후 응답을 `dong_code`로 비교한다. DBSCAN C번호만 비교하지 않는다.
- [ ] 지도 경계는 공식 GeoJSON을 사용하고 `dong_code`로 join한다. API에 없는 좌표를 추정하지 않는다.
- [ ] 노이즈 행정동은 '특이·개별검토형'으로 표시하며 군집 평균 추천과 혼동하지 않는다.
- [ ] Macro-F1 < 0.70 또는 Accuracy < 0.75 경고를 숨기지 않는다.
- [ ] 요청 중 로딩 표시와 422/네트워크 실패 재시도 UX를 넣는다.

## 해커톤 발표 전 최소 검증

1. 고정된 원본 스냅샷으로 배치 파이프라인을 2회 실행해 결과가 동일한지 확인한다.
2. 쉼터 1개 후보 위치를 추가해 영향 행정동의 `access_deficit`과 위험도 변화 방향을 수작업 검산한다.
3. 후보지 1개에 대해 시설 추천·근거·SHAP 그래프·Before/After KPI가 같은 `dong_code`를 가리키는지 검증한다.
4. 데이터 대체·미결합·쉼터 단독 대체 주의사항을 화면과 발표 자료에 노출한다.
